## 页面提供什么

- 选择五知识点中的一个或多个目标，创建演示学习标识；也可恢复原记录。
- 根据后端安排诊断、复习、练习或推进，选择答案后查看评分、解析与掌握度变化。
- 展示五知识点掌握状态，未取得证据时显示“待诊断”，不把先验包装成已测能力。
- 向助教显式提问，查看讲解、实际来源章节、工具完成情况与离线降级标记。
- 刷新后恢复最近 50 条答题回执与最近 5 次助教讲解；浏览本地课程片段。
- 切换学习标识保留原数据库记录，不提供清空学习历史的按钮。
- “我的笔记”管理Markdown原文、UTF-8导入、公式预览和多知识点关联；草稿恢复与revision保护独立于原答题流程，不调用模型或更新BKT。

页面为本地单人原型，使用演示标识，没有登录鉴权或多人访问隔离认证。标识用于筛选记录，不是权限凭证，不应把此版本直接部署为真实学生共用服务。

## 在当前电脑使用

前端已构建，启动后端后打开 [学习页面](http://127.0.0.1:8000/)。原 [接口文档](http://127.0.0.1:8000/docs) 继续可用。

```powershell
Set-Location D:\ZZUAgent
.\.venv\Scripts\python.exe -m uvicorn eduagent.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

本次协作启动的后台服务正在运行时，可以直接使用，勿重复启动。电脑重启、服务退出或关闭前台终端后，需要重新执行启动命令。构建后的页面由同一个 FastAPI 服务提供，演示时不需要另外运行 Vite。

首次学习可使用自动生成的演示标识，选择目标后点击“开始学情诊断”。提交一题后先查看反馈，再点击“继续下一步”。需要讲解时点击“讲解当前知识点”填入问题，再点击“发送给助教”。这个填入动作本身不会发模型请求。

当前每个知识点只有两道启用题目，答错后可能因缺少新题而暂停；此时仍可查阅资料和向助教提问。候选题的人工审阅与启用方式见 [内容审阅说明](CONTENT_REVIEW_GUIDE.md)。

本轮使用 Node 22.14.0、npm 10.9.2。开发与测试需要 Node 22 至少 22.12；完整允许范围见 [package.json](../frontend/package.json)，其他版本未验证。

```powershell
Set-Location D:\ZZUAgent
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e './backend[api,dev,agent]'

Set-Location frontend
npm.cmd ci
npm.cmd run test
npm.cmd run build
Set-Location ..
.\.venv\Scripts\python.exe -m uvicorn eduagent.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

固定依赖为 Vue 3.5.44、Vite 8.3.4、Vue 插件 6.0.10；测试使用 Vitest 5.0.5、Vue Test Utils 2.4.6、jsdom 26.1.0。完整传递版本由 [package-lock.json](../frontend/package-lock.json) 固定，安装到 `frontend/node_modules/`，不修改全局 Node。依赖解析选择了兼容现有 Node 的测试工具；安装会出现间接开发依赖的弃用提示，本轮 `npm audit` 返回 0 项已知漏洞。

前端开发时可在 `frontend/` 运行 `npm.cmd run dev`，打开终端显示的 5173 地址。Vite 将 `/api` 和 `/health` 代理到 8000；只绑定本地回环地址、端口固定，不增加全局跨域许可。设置方式参考 [Vite server.proxy](https://vite.dev/config/server-options#server-proxy)。源文件变化后，重新构建再重启后端加载资源挂载。

构建结果只包含页面及编译资源。后端只提供 `/` 和 `/assets/`，不会公开源码目录、题库文件或根目录配置。前端没有模型密钥配置，不使用 `VITE_` 字段传递密钥；DeepSeek 凭据仍只在后端的本地忽略配置中。

## 页面与服务如何配合

前端只保存学习标识与尚未确认的答案提交编号，掌握度、分数、题目分配、已评分回执和助教回答均从服务器读取。Vue 组件负责显示与事件，`useWorkspace.js` 组织流程，`api.js` 处理 HTTP，评分与 BKT 继续由原 Python 服务执行。

答题前先把 `decision_id`、`event_id` 与选项写入浏览器本地存储，再发送。遇到断网或响应丢失时保留原事件，重试和重载后仍提交同一编号，由后端返回原回执，避免重复更新。已明确返回过期或冲突的请求会同步后端状态；不会在前端猜测分数。

浏览器不允许本地存储时会阻止新答案发送，并说明原因。未确认的提交处理完之前，切换学习标识与模型提问会暂停，避免混淆归属。

模型请求只在显式发送且原问题检索有候选依据时触发，没有自动生成、自动重试或轮询。依据不足时 `model_calls=0`，直接保存本地学习安排；这不保证所有课程外意图都能识别，含课程词的问题仍可能误检。刷新调用历史查询；网络不确定时先刷新已有记录，再决定是否重新发送。重新发送可能产生费用。模型文本与资料片段均以纯文本转义显示，不执行返回的 HTML。

新增只读接口：

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/students/{student_id}/history?limit=50` | 返回该标识的已评分回执，按作答顺序倒序，最多 50 条 |
| `GET /api/v1/students/{student_id}/tutor-runs?limit=5` | 查询已保存讲解，默认 5 条、最多 10 条，不调用模型 |

原Web交付时未改题库/BKT/策略或schema2。后续Phase2已备份迁至schema3，仅增加笔记表，原学习事实保持；禁止旧程序连接新库，运行与回退见笔记说明。
