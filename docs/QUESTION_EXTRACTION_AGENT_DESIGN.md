# 原题提取改进：模型结构化与来源校验

状态：2026-10-22方案，尚未实施。用户要求先说明方案；已明确授权为提升提取质量直接调用模型，常规相关调用无需逐次确认费用。优先复用现有DeepSeek/LangGraph和资料服务，原资料选择及本轮外发范围继续受控。

## 现状与问题

审查`documents/question_extraction.py`确认：当前按题号和A～H格式分割，发现至少两个选项样式片段就判为single_choice；没有语义判断这些片段是选项、子问还是解答步骤。跨页拼接仍依赖题号，子问编号可能被当成新题。现有视觉能力主要做页面转录，提题仍回到规则。当前题库只区分single_choice/true_false/other，答案字段只适配选项ID，不能完整表达问答/计算/证明的原文答案。

所以需要同时调整提取流程与题目结构；仅修改提示词或再次OCR不足以解决所有问题。现有工程测试证明流程约束，不证明题型识别或内容完整性。

## 建议流程

读取选定资料的原文和原页 → 模型识别题目边界/层级/题型并输出结构 → 程序校验来源与结构 → 对缺项或冲突局部复核 → 展示问题与改动 → 人工确认入个人题库。

- 文本清晰的资料优先给完整相邻页文本；公式、表格、图片、分栏或已有缺项时同时提供原页图。不只发送已被规则切坏的草稿，避免原题缺失后靠猜测补全。已保存转录可复用，但原图仍可作为复核依据。
- 单一受控LangGraph工作流，允许读取本轮选定的当前版本解析、查看许可范围内的原页、提交候选结构。身份、资源版本、页码、调用预算由服务器绑定，不允许模型自行扩大来源、写正式题库或改掌握度。
- 模型识别题干、共享材料、父题/子问、真实选项、题型、原文答案/解析、公式/图表依赖、缺失或不确定项。只还原原题；未知字段为空并指出缺项，不补造答案或选项。
- 题型独立保存：单选、多选、判断、填空、简答、计算、证明、未确定；题型和可自动评分能力分离。首步支持完整入库/编辑/展示这些原题，原单选/判断评分保持。主观题文字作答可作为后续小步接入，模型批阅须独立设计，不承诺客观判分。
- 原文答案、模型推测参考、人工确认答案分别保留。提取节点不解题；生成参考解答如后续需要，是另一个明确功能，不能冒充原题答案。

## 校验与复核

严格JSON/类型校验只是第一层；还需校验文本证据实际存在、页码/单元来自本轮资料、选项和题型一致、子题层级完整、跨页续接与公式边界、原文覆盖及未解释缺项。页码由服务端绑定；无法对齐的片段保留原页位置并标记待核对，不能伪造精确字符位置。

校验不能证明语义完全正确。题型冲突、原文有内容而结构缺失等才触发局部模型复核；不为每题固定双调用，不无界循环。失败/超时保留原文和任务状态，未知执行状态不自动重发；用户可明确重试指定题或页。识别候选不自动覆盖已人工编辑/确认的题目，界面显示差异后才接受。

原题恢复按页面/段落顺序读取，不用只返回零散片段的RAG检索代替原题上下文。RAG可用于之后的知识解释，但不得用检索到的类似题目补齐当前题干。

## 实施次序与验收

1. 先修题型/原文答案/子问/缺项数据结构及旧题兼容，现有题目不自动重新分类。
2. 接入模型语义结构化与程序校验，复用选页、转录、任务幂等及审核入口。
3. 对缺失公式/图示、题型冲突等接入局部原页复核，显示具体缺项和版本差异。
4. 建立人工标注的固定测试集，覆盖问答/计算误判、子题、跨页、公式、图表、无答案及多题同页；分别统计边界、题型、题干/选项完整性、原文答案一致性与需人工修正比例。
5. 经所选资料外发授权执行真实模型验证，记录输入范围、模型/提示词版本、次数、耗时及实际失败。用同一批资料比较现有规则与新流程，不把JSON成功率或生成题数当成识别准确率。原正式评分/BKT/自评/历史回归保持。
