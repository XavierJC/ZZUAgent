## 自动检查做了什么

新入口只使用标准库，不读取模型配置、不调用 API、不修改题目状态或数据库：

```powershell
Set-Location D:\ZZUAgent
.\.venv\Scripts\python.exe -m eduagent.content_review
```

它检查已有题库契约、完全重复题干、重复选项、五知识点覆盖，以及原题目的保留；输出两套题库的内容指纹、数量、难度分布与校验状态。另有 21 个数值测试从题干条件独立计算候选答案，包括平方损失、更新步长、sigmoid、正则项和评估指标。它们不能自动判断所有概念题、表述歧义或教学价值。

若需为修订版生成新审阅单，明确指定一个尚不存在的文件：

```powershell
.\.venv\Scripts\python.exe -m eduagent.content_review --output docs/review/QUESTION_BANK_V2_NEXT.md
```

程序拒绝覆盖已有文件，避免丢失负责人写下的审阅意见。现有审阅单已经生成，不需再次运行生成命令。

## 负责人如何审阅

1. 按知识点逐题独立解答，检查正确选项是否唯一、定义是否明确、解析是否成立，再核对候选答案。
2. 检查知识点归属、难度、选项质量及是否适合本课程；有问题的题目记录修改意见，修订时更新题目版本。
3. 在审阅单登记实际审阅人、日期与意见。确实通过后，再在相应 JSON 题目中登记 `review_status=human_verified`、`reviewer`、`reviewed_at`。不能仅因自动测试通过就标记为已人工校验。
4. 单独阅读五份课程说明，核对公式、边界条件与来源许可；单独核对先修图。题库通过不等于资料或先修图通过。

本次没有代填审阅人、日期或人工验收结果。审阅人信息属于本地追溯资料，若公开仓库或演示材料，先确认适当的署名方式。

## 何时切换题库

现有 SQLite 数据库绑定题库内容指纹，题目与校验元数据变化都会导致新指纹。正式切换时使用独立数据目录和新数据库，并保留旧库供历史查询；不覆盖旧答题记录，不静默把旧记录解释为新题库的结果。本轮测试已确认候选包无法绑定旧数据库，失败后原答题回执仍能恢复。

待人工审阅完成后，按新题库再检查：答错后是否有足够新题、全课程能否结束、答案过滤与重启恢复是否正常。候选集的合成测试已验证“连续两次答错 → 复习三道新题并答对 → 达到演示阈值 → 进入梯度下降”，仅证明程序行为。

默认累计作答上限仍为每个演示学生 20 次；40 题是候选题库容量，不意味着每个学习过程必须答完 40 题。题目耗尽或达到上限仍明确停止，不反复使用同一道题凑掌握度。
