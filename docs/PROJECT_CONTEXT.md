## 1. 项目定位

- **项目名称**：智学郑大 EduAgent——基于知识追踪与智能体驱动的个性化学习辅助系统。
- **比赛**：郑州大学首届 AI 智能体创新应用大赛。
- **选题**：附件 1 的 A2，AI 助教·“教、学、评”闭环与个性化学习（含 AI 通识实验室）。
- **团队**：1 人独立开发。
- **目标用户**：学习高校《机器学习》课程、需要诊断薄弱知识点和安排后续练习的学生。
- **当前基础**：经单独授权完成Phase4A，Studio增加独立四级自评/信心、主客观对照、确定性重点及可选受控指南/历史，BKT与正式推进保持。清单仍0.4.1，355/101项回归与构建通过，schema5备份迁至6，原12表摘要不变；18组隔离HTTP、9次模拟模型、0次真实模型，3A/3B记录独立保留。课程55例与5/15课程外误检、40候选题待审仍保留，当前仍原10题。浏览器人工验收、真实模型预算、内容审阅与真实学习效果未完成；总结/卡片、教材/图片、后续阶段不自动实施。
- **开发者基础**：已有 Python、C++、机器学习、PyTorch、Transformer 基础，正在学习 Agent 算法与应用工程。协作中需解释重要设计与运行机制。

系统根据答题证据估计知识掌握状态，并用该状态驱动教学行动。课程问答是闭环的一部分，核心目标是使诊断、学习、测评和计划更新能够连续执行。

## 3. 用户已确认的目标与范围

### 完整学习流程

学生学习目标 → 初始学情诊断 → 知识讲解 → 智能组卷与测评 → 更新掌握度 → 规划后续内容 → 继续学习或阶段总结。

初始 BKT 先验值只表示模型假设；需取得答题证据后才能给出诊断解释。达到演示阈值仅表示该参数设置下的模型判断。

### 五项核心功能

| 功能 | 目标行为 | 可检查证据 |
| --- | --- | --- |
| 课程知识问答 | RAG 检索课程材料后回答，提供出处；检索证据不足时明确说明 | 回答与检索片段、资料名及页码或章节对应 |
| 学情诊断 | 根据答题记录，用自主实现 BKT 计算每个知识点的掌握概率 | 参数、输入答题、计算前后状态可追溯 |

应用以单体服务和本地存储为主。知识检索、组卷、评分、BKT 更新通过明确工具接口组合，避免把算法和业务数据写入提示词逻辑。

已确认的阶段顺序：离线核心 → FastAPI → 模型/检索 → Vue。目前四项工程基础已实现，Vue 仍待真实浏览器人工验收。用户已授权使用 DeepSeek API，本地配置位于被忽略的 `.env`，密钥不得进入源码、前端产物、文档或日志。已完成真实模型验证；这不表示课程内容已审阅或学习效果已证明。

### Agent 与确定性工具的分工

- BKT 保存量化状态，Agent 根据这些状态选择或解释下一步行动。
- 模型可选择检索、讲解、复习和练习等允许行动；客观题评分与概率更新由程序执行。
- 提交答案后，应用按固定顺序完成评分、BKT 更新与事务保存，避免模型遗漏更新或重复写入。
- SQLite 是学习事实来源；LangGraph 运行状态与对话历史不能替代学习记录。
- 所有规划均记录简明依据，如目标知识点、掌握度、最近错误和先修条件；不依赖输出模型内部推理过程。
- 外部模型不可用时可切换到明确标注的离线规则演示，真实模型与离线模式分别验收。
- 当前图工具只读学情、检索课程并创建合法练习分配，不拥有评分或概率写入权限。模型只接收练习分配元信息，题干、选项和答案不发送给模型。
- 模型引用检查验证 ID 属于实际检索结果、正文与来源列表一致；不把该结构检查等同于内容事实正确性证明。
- 2026-10-20 已拦截单字重叠造成的宿舍电费误检；挑战集仍有同名课程的管理类问题误检。开发集数据不代表通用准确率，后续需语义相关性改进和独立人工标注验证。
- 资料不足时不发送模型请求，返回真实规则学习安排；有依据时模型检索来源仍受原问题候选章节约束。该限制不能证明句子级事实对应或完整意图相关。
- 前端不计算分数或掌握度。答案使用持久化事件编号重试；模型只在显式发送提问时调用，刷新读取保存讲解，避免自动重复计费。

## 5. BKT 建模约定与局限

第一阶段已采用按知识点独立、无遗忘的标准四参数 BKT；每道题只映射一个主要知识点。题目难度用于选题，不宣称已进入 BKT 概率模型。

设当前掌握概率为 `p`，初始先验为 `P(L0)`，学习转移概率为 `T`，失误概率为 `S`，猜测概率为 `G`。先根据答题证据计算后验 `q`，再计算下一次学习机会前的状态 `p_next`：

```text
答对：q = p(1-S) / [p(1-S) + (1-p)G]
答错：q = pS / [pS + (1-p)(1-G)]
转移：p_next = q + (1-q)T
```

阶段一需记录并区分 `p`、`q` 与 `p_next`。只有实际评分的答题事件触发一次更新，单纯浏览讲解不更新 BKT。退化参数导致观测概率为零时应明确报错，不伪造概率。

参数和掌握阈值均为演示设置，未用真实学生数据拟合，不能解释为测量得到的真实能力。少量题目、独立知识点和无遗忘假设限制诊断精度。同一道题反复练习也不等价于独立能力证据。

方法参考：Corbett 与 Anderson（1995），[Knowledge tracing: Modeling the acquisition of procedural knowledge](https://doi.org/10.1007/BF01099821)。具体实现需以公式和可独立核验的数值测试为准。

## 6. 拟体现的创新与验证

1. **量化学情**：用 BKT 接收答题证据，为建议提供可检查的状态依据。
2. **状态驱动规划**：结合掌握度、错题和先修关系改变后续行动。
3. **可执行闭环**：将学习、测试、反馈和计划更新连接为可运行流程。
4. **可解释与可验证**：保存决策依据、资料引用与工具结果，支持复现。

这些是拟实现的应用特色，不宣称发明 BKT 或已证明提高学习成绩。

验证按三层区分：算法与存储正确性测试；合成答题情景的闭环与策略对比；有条件且获得同意后的少量真实试用。合成情景可比较固定顺序与自适应策略的选题/行动变化，不能据此报告学习效果提升。真实效果需记录样本量、设置、实际结果及限制。

已完成的 [有限教学决策对比](POLICY_EVALUATION.md) 在同一重放学情上查询当前规则与每知识点固定两题基线，不构造分叉后的假想答题。八个状态共享历史前缀，仅验证下一步行为；三处避免薄弱先修推进的同时，当前小题库也产生三次暂停，需共同报告。
