# Phase4B-2实施设计

2026-10-22。用户正式授权4B-2。已只读核对现库schema7/21表、1份PDF/3个local_extraction单位、完整性ok、外键0；未输出课件正文。4B-1接口/解析单位与文档头版本、既有只读GuidanceService可复用，没有重大架构冲突，不增加依赖或收费模型。

采用SQLite中独立的小规模版本快照，避免章节/关联分批提交造成半发布：architectures保存作用域和独立CAS revision；drafts保存严格验证的JSON图；versions保存不可变发布图；entities是章节/概念稳定UUID身份账本；candidate_batches保存规则候选与服务端来源证据；operations保存按学生/课程/request_id幂等回执。拟增6表，schema7→8，原21表保持。图本身包含独立chapters/concepts、概念多章节关联与relations；名称不作唯一键，身份账本为4B-3的映射外键预留。首版限25体系、每体系50发布版本、100章节/150概念/300关系、10层章节；草稿请求256KiB，持久图512KiB。

草稿以完整图原子保存，章节/概念分别稳定ID；发布须明确confirmed=true。发布是独立不可变快照，发布后的草稿锁定；后续编辑显式创建新草稿，旧发布内容不动。变更有引用节点须先显式调整对应边/章节关联，否则整次提交拒绝；历史身份不物理删除。发布前重复验证结构、来源与版本，整个发布及回执同事务。

contains为概念整体→组成概念，有向无环；related_to为对称关系，UUID排序规范化、禁止反向重复；prerequisite_candidate为先修候选→后续概念，禁止自环/重复/环，始终未确认，不因体系发布写入正式先修图。章节父子无环，章节不是概念，章节归属不是概念contains边。

规则候选仅从明确选中的当前本地解析读取（不外发、默认不采纳视觉转录）：MD标题、PPTX真实标题、PDF/TXT显式编号标题；概念来自“概念/定义/关键词”标记或有限课程术语的完整标题匹配，不把全部标题都变成概念、不按同名合并、不推断先修。保留未分类位置。候选批次固定文档/文件版本/hash/run/unit、位置、原文截取偏移和证据；客户端仅引用batch/item，不可伪造证据。来源变化显示modified/deleted/reparsed/unavailable并阻止旧候选发布；历史证据快照保留、不会被新文件静默覆盖。

API为学生子资源knowledge-architectures：列表/创建、详情、草稿PUT/从发布版本开草稿、发布/版本列表/版本详情、候选批次生成/查看、来源依据与概念正式学情GET、请求回执。正式导航只显示发布版本，草稿有明确编辑模式。学情复用一致的只读GuidanceService快照；关联仅显示正式知识点的状态，未作答为待诊断，未关联为无正式测评，不分配练习、不写BKT/自评。

前端在资料工作台加独立课程知识体系视图；左侧发布/草稿、搜索与可展开树，中间概念/章节编辑及关系，右侧关联学情/入口；小屏堆叠。本地草稿/回执按学生/体系隔离，切换保护未保存内容、刷新只GET、网络不明不自动重发；保留既有笔记草稿。
