# 聊天回答字段兼容修复

2026-10-21。20:10:26这轮工作台请求已收到DeepSeek输出（1次模型调用、输出551 token），被本地`invalid_fields`校验拒收。旧回执没有保存模型JSON形状，不能断言当时具体多出或缺少哪个字段。本轮修复接收契约，保留来源和工具边界。

## 接收规则

聊天优先使用标准`answer/citation_ids/supplement_md`。接收器兼容明确、可验证的显示格式：

- 回答别名：`answer_md/answer_markdown/response/response_md/content/explanation`。
- 引用列表别名：`citations/references`；对象形式只提取`citation_id`或一致的`id`。标题、原文、版本等字段全部从服务端实际片段恢复，不信任模型提供的元数据。
- 补充别名：`supplement/supplemental_md/model_knowledge/additional_knowledge/general_knowledge/general_answer/extension_md`。
- 单层`data/result/response`结果包装或单元素数组；多答案、冲突字段不猜测选择。
- 无关显示元数据（如标题、状态、来源说明）不导致整个回答被丢弃，也不复制进权限、用量、模型配置或评分。模型输出的`sources`绝不用于检索或权限判断。
- 缺少引用数组时，仅从正文中已有的规范引用标记提取编号，再按实际取得片段校验；没有引用的通用解释仍明确标注为模型知识。不会按资料ID/标题猜造引用。

未知引用、伪造引用、冲突别名及身份/权限/评分/SQL/工具控制字段仍拒绝。工具调用权限、学生与来源版本由原不可变上下文决定，不从模型回答重新构造。

学习指南继续严格要求原两字段及规则边界，不采用聊天的显示兼容策略。JSON语法、长度、重复键与原文引用检查继续执行；代码围栏只兼容完整JSON，不任意截取花括号或修复公式转义。

## 明确错误与隐私

新增错误：`missing_answer`（没有可识别正文）、`ambiguous_fields`（字段或包装冲突）、`forbidden_output_fields`（出现控制字段）。

新增可空`validation_summary`，仅记录根结构类型、已知字段名及未知字段数量。不保存未知键名或任何字段值，避免把笔记内容写进诊断。旧记录返回空摘要，不伪造此前JSON形状；不重写失败记录或自动重发。

没有新增依赖、服务、API路径或数据库列。schema6/29路径保持；新摘要仍放入既有`result_json`。BKT、评分、正式题库、指南策略不变。
