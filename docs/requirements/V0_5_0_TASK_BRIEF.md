# EduAgent v0.5.0 设计与开发任务书

## 一、项目背景

项目名称：EduAgent——基于知识追踪与智能体驱动的个性化学习辅助系统。

本项目参加郑州大学首届 AI 智能体创新应用大赛，对应官方 A2“AI助教·教、学、评闭环与个性化学习”赛题。

目前项目版本为 v0.4.1，已实现：

- Python + FastAPI 后端
- Vue 3 + Vite 前端
- LangGraph 单一 Agent
- DeepSeek 模型调用
- FAISS + TF-IDF 课程检索
- SQLite 学习记录与状态持久化
- BKT 贝叶斯知识追踪
- 自动评分、学习规划、课程问答
- 基础学习闭环及相关自动化测试

请先阅读项目中的：

- AGENTS.md
- docs/PROJECT_CONTEXT.md
- docs/DEVELOPMENT_PLAN.md
- README.md
- 现有前后端代码、数据结构和测试

本次开发采用增量升级，不推翻既有系统。

## 二、v0.5.0 开发目标

将当前固定课程的学习智能体扩展为支持个人笔记、Markdown/LaTeX 与个性化知识检索的学习系统。

核心目标：

1. 全站统一支持 Markdown 和 LaTeX 公式显示。
2. 实现可编辑、可保存、可导入的个人学习笔记。
3. 将笔记构建为可检索的个人 RAG 知识库。
4. 支持笔记与现有课程知识点关联。
5. 保存知识点自我评价，并与客观 BKT 掌握度分离。
6. 让 Agent 在讲解时按用户请求利用课程资料和个人笔记。

此版本暂不开发 PDF 教材解析、复杂章节知识图谱、图片习题识别或通用多课程管理平台。

## 三、功能模块 A：统一 Markdown / LaTeX 渲染

### 技术建议

优先评估以下方案：

- Markdown：markdown-it
- 数学公式：KaTeX
- 代码高亮：highlight.js 或 Shiki
- 编辑器：CodeMirror 6，或先采用轻量 textarea
- 安全处理：DOMPurify 或等效安全清理方案

请优先检查项目中是否已有同类依赖，避免重复引入。

### 功能要求

支持：

- 标题、段落、列表、引用、表格
- 行内代码和代码块
- 行内公式：`$...$`
- 块级公式：`$$...$$`
- 常用 LaTeX 数学符号、上下标、分数、矩阵
- 代码语法高亮
- 长公式横向滚动
- 暗色或浅色主题下的合理显示

统一封装 MarkdownRenderer 组件。

该组件需要在以下位置复用：

- Agent 回答
- 课程知识讲解
- 习题题干
- 习题解析
- 检索结果
- 学生笔记预览

不得使用未经安全处理的 v-html 直接渲染不可信内容。禁用危险 HTML、脚本和不安全链接协议。

### 验收

使用固定 Markdown/LaTeX 测试集，验证公式、代码、表格、特殊字符和恶意 HTML 的渲染行为。

## 四、功能模块 B：个人学习笔记

### 前端

新增“我的笔记”功能入口。

建议包括：

1. 笔记列表
2. 新建笔记
3. 编辑笔记
4. Markdown 实时预览
5. 保存和删除
6. Markdown/TXT 文件导入
7. 按标题或知识点搜索
8. 笔记关联知识点
9. 笔记索引状态显示

笔记编辑采用左右分栏或“编辑/预览”切换方式。窄屏时自动切换单栏布局。

支持保存状态提示，避免切换页面造成内容丢失。

### 后端

使用现有 SQLite 存储结构化数据。

建议新增 notes 表，字段包括：

- id
- student_id
- title
- content_md
- course_id
- created_at
- updated_at
- revision
- content_hash
- deleted_at（可选）

笔记与知识点允许一对多关系，建议建立 note_knowledge_points 关联表，而不是把多个知识点塞入字符串字段。

所有笔记必须按学生身份或当前演示用户作用域隔离。

### 数据操作

提供创建、查询、更新、删除、导入笔记的接口。

建议 REST 风格：

- GET /api/notes
- POST /api/notes
- GET /api/notes/{id}
- PATCH /api/notes/{id}
- DELETE /api/notes/{id}
- POST /api/notes/import

以上路径仅为建议，实施前检查现有 API 前缀和项目习惯，避免冲突。

更新时使用 revision 或等效机制防止旧数据覆盖新内容。

导入支持 UTF-8 Markdown 和 TXT，限制文件大小，校验文件内容；不要仅依据文件扩展名信任上传内容。

原始 Markdown 是权威保存内容，渲染 HTML 可以按需生成，不应作为主要存储格式。

## 五、功能模块 C：个人 RAG 知识库

### 核心原则

系统维护两种不同的知识来源：

1. Course Knowledge Base：课程资料与教材内容。
2. Personal Knowledge Base：用户自己创建或导入的笔记。

二者可在同一查询中组合检索，但必须保持来源隔离、用户隔离及引用可追溯。

不得把学生笔记自动升级为权威课程知识。

### 索引设计

新增个人笔记索引管理模块，尽量复用现有 FAISS/TF-IDF 检索能力。

索引片段建议包含：

- source_id
- source_type
- student_id
- course_id
- knowledge_point_ids
- title
- chunk_id
- content
- content_hash
- source_revision

处理流程：

笔记创建或修改 → 内容校验 → Markdown 文本提取 → 分块 → 更新索引 → 记录索引状态。

笔记删除后，对应片段必须从可见检索结果中移除。

如现有 FAISS 方案不适合直接删除或更新单条向量，可以采用版本化重建或按用户重建索引。

原始笔记与索引保持独立；索引失败不能破坏原始笔记。

### 检索功能

支持：

- 仅检索课程资料
- 仅检索个人笔记
- 联合检索两类资料
- 根据 student_id、course_id 及来源类型过滤
- 返回引用来源和原始片段
- 知识不足时明确说明，不编造依据

必须在检索前或检索过程中执行权限过滤，不能只在检索结果返回后隐藏其他用户内容。

### Agent 接入

扩展现有 LangGraph 的检索工具。

当学生提出问题时，Agent 可以根据当前上下文检索课程资料和个人笔记，引用不同来源并进行讲解。

例如：

“结合我的梯度下降笔记，解释为什么学习率过大会导致发散。”

回答应区分：

- 课程资料中的结论
- 学生笔记中的内容
- 模型进一步给出的解释

若个人笔记与课程资料冲突，应提示存在不一致，而不是直接相信学生笔记。

检索内容视为不可信数据，不执行笔记或文档中的提示词指令。

## 六、功能模块 D：知识点关联与自我评价

### 知识点关联

允许学生把一篇笔记关联到现有5个机器学习知识点。

本版本暂时不允许个人笔记自动修改正式知识点先修关系。

可以通过标题、关键词或模型生成候选关联，但必须允许学生确认或修改。

### 自我评价

新增知识点自评功能，建议采用四个等级：

1. 完全不了解
2. 理解基本概念
3. 能完成基础习题
4. 能独立应用和解释

可附加1～5级学习信心。

建议新增 knowledge_self_assessments 表，记录：

- student_id
- knowledge_point_id
- level
- confidence
- assessed_at

保留必要历史，方便展示自评变化。

### 与 BKT 的关系

自我评价和 BKT 掌握概率是两种不同数据，不得直接互相覆盖。

禁止因为：

- 用户上传了笔记
- 用户声称已经掌握
- Agent 完成了一次讲解

就直接增加 BKT 掌握概率。

BKT 仍按既有正式评分事件和参数版本更新。

Agent 可以参考自评和客观掌握度之间的差异，推荐追加诊断或复习，但不能自行修改评分事实。

## 七、前端设计要求

保留现有 EduAgent 蓝白简洁科技风。

不要大规模重构原有页面。

建议侧边栏增加：

- 学习工作台
- AI 学习助手
- 课程资料
- 我的笔记
- 学习记录

如果现有导航名称不同，可以采用最小调整。

我的笔记页面需要清楚区分：

- 编辑模式
- 预览模式
- 保存状态
- 索引状态
- 关联知识点

页面应提供空状态、加载状态、失败状态和删除确认。

支持键盘操作、合理对比度、窄屏适配及公式横向滚动。

避免只做静态页面，所有主要交互需要连接真实后端。

## 八、数据安全与迁移

1. 不得破坏既有评分、BKT、学习历史和 Agent 记录。
2. SQLite 变更采用版本化迁移。
3. 迁移前备份数据库。
4. 不得删除或覆盖历史学习事实。
5. API 不应暴露其他学生的笔记。
6. 对 Markdown 和文件导入做大小、格式及安全检查。
7. 现有模型密钥继续保存在本地环境配置中。
8. 新增 RAG 索引不能影响正式课程资料的检索结果。
9. 索引失败时应有明确状态，并可重试或重建。
10. 不得声称自评数据是经过验证的客观掌握度。

## 九、开发实施顺序

### Phase 1：Markdown/LaTeX 渲染

实现统一渲染组件，覆盖题目、解析、Agent 和课程资料。

完成安全性、公式及响应式测试。

### Phase 2：笔记管理

实现 SQLite 模型、API、Vue 编辑器、Markdown 导入和持久化。

完成创建、编辑、删除、刷新恢复及用户隔离测试。

### Phase 3：个人 RAG

完成笔记分块、索引、更新、删除、来源检索及 Agent 工具接入。

重点测试索引更新一致性和跨用户权限隔离。

### Phase 4：知识点与自评

实现笔记与知识点的关联、自我评价记录和基础展示。

Agent 可以读取这些信息并提供建议，但 BKT 不受自评直接影响。

### Phase 5：端到端验收

验证以下场景：

A. 创建包含 LaTeX 公式的笔记，保存后刷新并正确恢复。

B. 导入 Markdown 笔记，检索返回真实笔记内容及来源。

C. 修改笔记后，检索返回新内容，旧内容不再作为当前版本出现。

D. 删除笔记后，检索不再返回被删除的内容。

E. 两个学生拥有同名笔记，检索结果严格隔离。

F. 用户记录自评，客观 BKT 掌握度保持不变。

G. Agent 结合个人笔记和课程资料回答问题，并正确标注来源。

H. 现有答题、评分、BKT、历史恢复及练习规划仍然正常。

I. 不可信 Markdown、恶意链接、异常文件及索引失败可以被安全处理。

## 十、开发约束

当前参赛团队仅1人，比赛时间紧张。

优先完成可靠、可演示的最小系统，不增加复杂多智能体、全学科知识图谱或不必要的基础设施。

不擅自调整 BKT 参数、正式题库、学习推进策略或已保存的评分事实。

现有 v0.4.1 的人工内容审阅、课程外检索误检和浏览器验收问题仍需保留在开发计划中，不能因为增加新功能而标记为完成。

每个阶段必须：

- 说明修改文件
- 说明设计决策
- 编写必要测试
- 运行可以执行的测试
- 记录实际通过与失败情况
- 更新 DEVELOPMENT_PLAN.md

不要将模拟测试、AI 判断和真人学习效果混为一谈。
