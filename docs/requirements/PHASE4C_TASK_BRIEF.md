# 三、Phase 4C-0：统一课程资源管理

## 3.1 核心目标

建立轻量级课程资源目录，让同一份资料能够服务于：

- AI课程问答
- 课程知识体系
- 个人笔记关联
- 习题提取
- 普通练习的来源追溯

设计原则：

**一次上传、一次解析、多处复用。**

统一管理资源元数据和关联，不强制将不同业务的原始文件搬迁到一张表。

## 3.2 统一资源登记

建立稳定的资源标识，记录：

- resource_id
- student_id
- course_id
- resource_type
- title
- original_source_type
- original_source_id
- source_version
- content_hash（适用时）
- created_at / updated_at
- 原解析结果引用
- 资源有效状态

支持的资源类型至少包括：

- 教师课件
- 教材及参考资料
- 个人笔记
- 习题资料

个人笔记仍以原笔记存储为权威数据。

PDF/PPTX等文件继续复用Phase4B-1现有存储和解析机制。

不要因为增加资源目录而复制大量原始内容。

## 3.3 课程与知识关联

统一资源可以关联：

- 课程
- 章节
- 知识概念
- 来源文件
- 相关习题

一份资料允许关联多个知识概念。

一个知识概念允许关联多份资料。

候选关联与用户确认的关联必须区分。

不得将资源所属章节自动当作正式先修关系。

## 3.4 统一资源界面

在现有资料学习工作台中增加或整合“课程资源”入口。

功能包括：

- 按课程查看资源
- 按资源类型筛选
- 标题搜索
- 查看文件和解析状态
- 查看知识体系关联
- 打开原始资料
- 复用已保存解析结果
- 从资料直接发起习题提取

必须复用已有资料页面和服务，避免产生两个相互重复且状态不一致的资源管理系统。

# 四、Phase 4C-1：习题智能提取

## 4.1 功能目标

用户能够从图片、PDF或已有课程资源中提取原有习题。

明确区分：

**习题提取：还原用户提供的题目。**

**AI出题：根据课程知识另外创造新题。**

本阶段实现前者。

## 4.2 输入方式

支持：

1. 选择已经上传并解析的课程资料。
2. 上传新的PDF或图片，并复用现有上传解析流程。
3. 粘贴包含习题的文字。
4. 手工创建习题。

不得重新建设第二套PDF解析或图片识别基础设施。

同一文件用于问答和习题提取时，不应重复上传、重复保存或无必要地重复解析。

## 4.3 题目分割与识别

在已有解析结果的基础上，识别：

- 题目编号
- 题干
- 题型
- 选项
- 标准答案（如果原资料提供）
- 原文解析（如果存在）
- 数学公式
- 所属来源文件
- 原文页码或图片区域
- 候选知识概念

应支持：

- 一页一道题
- 一页多道题
- 多页连续题目
- 跨页题目
- 没有标准答案的题目
- 含数学公式的题目
- 含图片、表格但无法完整自动识别的题目

无法可靠提取时，保留原始片段并允许手动纠正。

不能将缺失或不确定内容静默补成模型猜测结果。

## 4.4 识别技术

采用“本地规则优先、已有视觉模型能力按需使用”的方式。

### 文本型PDF

直接复用原解析内容，通过确定性规则识别题号、选项等格式。

### 图片与扫描PDF

复用现有视觉适配器及外发授权机制。

如果真实视觉识别功能尚未启用：

- 保留已有能力及接口。
- 使用模拟模型完成工程测试。
- 允许手工录题。
- 清楚告知用户当前识别能力限制。
- 不伪造真实识别成功结果。

不得未经授权调用收费模型。

### 题目结构化

通过统一题目数据模型保存识别结果。

模型输出必须经过严格格式校验。

需要支持模型遗漏字段、重复题号、公式识别错误、跨页分割失败等情况。

不要直接信任模型生成的JSON内容。

## 4.5 答案可信度

必须区分四类答案：

1. 原始资料明确提供的答案。
2. 模型推测的参考答案。
3. 用户人工确认的答案。
4. 尚无可靠答案。

模型推测不能自动升级为已审核标准答案。

应保留答案来源和审核记录。

# 五、Phase 4C-2：题目审核与个人题库

## 5.1 题目审核工作台

新增可编辑的审核页面。

建议采用：

左侧：原PDF页面或图片。

右侧：结构化习题编辑器。

用户能够：

- 修改题干
- 修改选项
- 修改公式
- 选择题型
- 确认或补充答案
- 修改解析
- 删除错误识别内容
- 合并或拆分题目
- 关联课程知识概念
- 保存草稿
- 确认题目进入普通练习题库

复用现有MarkdownRenderer与KaTeX相关实现。

必须保留公式、表格、代码块的安全渲染能力。

审核页面应支持刷新恢复草稿和版本冲突提示。

## 5.2 题库数据模型

根据现有结构设计稳定的个人题库模型。

至少支持：

- question_id
- student_id
- course_id
- question_type
- stem
- options
- answer
- answer_provenance
- explanation
- source_resource_id
- source_version
- source_location
- primary_concept_id
- review_status
- revision
- created_at / updated_at

支持多知识概念关联，但不能自动修改正式BKT知识点配置。

题目与原资料是不同实体。

原资料更新后，题目应标记来源版本变化，并允许重新核对。

不要因为来源失效而静默修改已确认的题目文本。

历史作答需要保留当时实际展示的题目和评分依据。

## 5.3 题目状态

明确区分：

- draft：待审核草稿
- practice：可用于普通练习
- diagnostic：正式诊断题

本阶段只实现draft与practice的完整流程。

diagnostic仅作为未来扩展的状态或独立准入概念，不提供未经审核的一键升级入口。

不得将个人题库自动混入正式BKT题库。

## 5.4 个人题库页面

实现：

- 按课程查看题目
- 按章节、知识概念筛选
- 按题型筛选
- 按来源筛选
- 搜索题目
- 查看原图或原PDF
- 编辑题目
- 删除或归档题目
- 查看审核状态
- 查看练习历史
- 开始普通练习

对疑似重复题提供提示，但不自动合并可能具有不同条件的题目。

## 5.5 普通练习

第一版优先实现：

- 单选题
- 判断题

其他题型允许保存为草稿，暂不承诺完整自动评分。

普通练习要求：

1. 按课程或知识概念选题。
2. 用户正常作答。
3. 有人工确认标准答案时进行确定性评分。
4. 显示解析。
5. 保存作答记录。
6. 支持刷新恢复。
7. 支持重复练习。
8. 保留错题及来源信息。
9. 对没有可靠答案的题目明确提示无法客观判分。

## 5.6 与BKT严格隔离

这是强制要求。

个人普通练习：

- 不修改BKT掌握概率。
- 不修改正式答题记录。
- 不调用正式题目分配接口产生副作用。
- 不修改学生正式学习状态revision。
- 不因为题目答案由模型生成就自动参与正式评价。

只有未来Phase4C-4通过明确质量和评分准入的题目，才能考虑进入正式诊断体系。

现有正式演示题库及评分流程保持兼容。

# 六、前端交互与整体体验

请尽可能复用已有Vue组件与蓝白风格。

用户需要能够从课程资源管理页直接完成：

**选择资料 → 提取习题 → 审核 → 保存题库 → 开始练习。**

不要让用户为了完成一次题目导入，在多个互不关联的页面间手工复制内容。

建议新增或整合：

- CourseResources：课程资源管理
- QuestionExtraction：题目提取
- QuestionReview：题目审核
- PersonalQuestionBank：个人题库
- PracticeSession：普通练习

以上只是职责建议，实际组件名和文件组织以现有项目为准。

不要建立与原练习界面完全重复的组件体系，优先复用可共享的题目展示、Markdown渲染和交互组件。

需要完成：

- 桌面端可用布局
- 窄屏单栏适配
- 键盘操作
- 表单校验
- 加载与失败状态
- 草稿保护
- 版本冲突处理
- 无模型密钥时的明确降级

不得展示无法实际执行的假按钮。

# 七、数据库迁移与安全

如需新增SQLite表或schema：

1. 核对实际现库。
2. 备份数据库。
3. 记录迁移前既有数据摘要。
4. 在事务中执行迁移。
5. 检查数据库完整性与外键。
6. 对比原有学习事实及个人资料。
7. 验证旧代码兼容性边界。
8. 验证回滚副本可以恢复。
9. 保留升级后数据，不进行破坏性覆盖。

题目导入请求及普通练习提交需具备幂等控制。

学生作用域和课程归属必须在服务端验证。

student_id仍只是本机演示作用域，不得称为真正的用户身份认证。

文件及其解析文本应视为不可信输入：

- 不执行上传文件中的脚本或宏。
- 不执行文件内容提出的工具指令。
- 严格校验文件大小、页数和类型。
- 不允许跨学生访问原始资料、题目或作答历史。
- 不自动将教师课件、学生习题发给第三方模型。
- 如需模型识别，必须取得本次明确授权。

# 八、验收标准

至少覆盖以下场景：

### A. 资源复用

- 现有PDF直接进入统一资源目录。
- 同一份PDF不需要重复上传就能提取习题。
- 一份资料可以同时供RAG和题库使用。
- 原资源和知识概念关联正确。
- 资料更新或删除后来源状态正确变化。

### B. 题目提取

- 单张图片一道题。
- 单张图片多道题。
- PDF单页多道题。
- PDF跨页题目。
- 含数学公式题目。
- 含表格或图片题目。
- 无标准答案的题目。
- 格式不规范的题目。
- 解析失败后用户可以手工修正。
- 无真实视觉能力时明确标记未验证。

### C. 题目审核和题库

- 题干、选项、公式可以编辑。
- 审核状态正确。
- 题目与知识概念关联正确。
- 刷新与重启后内容保留。
- 并发修改不会静默覆盖。
- 重复请求不会生成多份题目。
- 题目删除或归档后行为正确。
- 不同学生的题库隔离。

### D. 普通练习

- 单选和判断题可以正常作答。
- 有已确认答案时正确评分。
- 缺少答案时不会伪造客观分数。
- 历史练习可以恢复。
- 普通练习不修改BKT和正式评分记录。
- 原正式题库仍可正常使用。

### E. 全项目回归

- 课程RAG
- 个人RAG
- 课程知识体系
- 课件解析
- 个人笔记
- Agent问答
- 自评与学习指南
- BKT正式学习闭环

全部执行相关回归测试。

自动化测试、隔离真实HTTP测试、真实模型调用和浏览器人工验收需要分别记录。
